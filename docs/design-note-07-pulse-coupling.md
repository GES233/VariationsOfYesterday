# 设计札记 07 — 脉冲耦合链路（水晶链路）与相位同步

> 状态：**事件层现行规范，数值已与原型对齐**。实现见 `src/main/scala/moe/chestnut/awa/voy/inner/mandate/PulseCoupling.scala`，数值指纹见 `src/test/scala/moe/chestnut/awa/voy/inner/mandate/PulseCouplingSpec.scala`。来源：云端 Agent 对 `inner/mandate` 的 Python 复现（`mandate/coupling.py` 与《脉冲耦合同步实验》笔记），本札记把它的结论固化进本仓库。

## 0. 一句话

格与格之间的「水晶链路」**只借用地脉的相位通道**：一枚格子的尖峰，隔一段固定延迟，向另一枚格子投一枚小面积脉冲。它能自己涌现锁相，但**锁不住漂移**——所以玩家必须学会测量、必须能编程。这条「机制自带的不稳定性」是本作工程玩法的地基。

---

## 1. 通道定义：只加通道，不动方程

```scala
PulseLink(src, dst, area = 0.5, transmitter = CrystalLink, delay = 1.0)
```

链路只做一件事：`src` 触发时，在 `src` 的尖峰时刻加 `delay` 后，向 `dst` 投递

```scala
FirePulse(dst, area, transmitter)   // 先设 dst.synapseTau = transmitter.tau，再 firePulse(area)
```

三条纪律与原型逐条一致：

1. **只走 p 通道。** 不碰 `u`（持续扰动）、`c`（主动安抚）、`c0`（基线安抚）。链路**不能搬运土地应力**；应力只按各格自身的 `ds/dt` 演化。
2. **不进入 RK4 向量。** `alpha` 突触核仍是步间闭式推进（`MandateState.step`），所以加了链路之后，单格轨迹仍与契约指纹逐位一致。
3. **与 `MandateGrid` 的扩散/平流正交。** 后者是物质性的应力输运（慢变量），前者是事件性的相位耦合（快变量响应）。两者可以叠加，但不是同一件事。

因此 `FirePulse` 事件携带的是**发射器种类**而非裸数值：`PulseTransmitter` 闭枚举里，铃/铜钲是 `Bell`（`tau = 5.0` 的 α 冲击核），水晶链路是 `CrystalLink`（`tau = 2.0` 的窄核）。`tau` 是**发射器类型的固有常数**，协议上不存在可填的数值字段——玩家或任何发射源都无法随意改 τ，新增发射器是一次引擎改动（设计裁定），不是运行时输入（2026-11-07 由裸 `tau: Double` 收紧为闭枚举）。DTO 里显式命名发射器，是让「快变量到底收到了什么」只由事件流描述——耦合回放才能确定。

## 2. 两条尖峰判据：相位传感 vs 事件传感

链路什么时候算「源格开火了」？原型用 Poincaré 截面上穿（`v` 向上穿过 `1.2`）。这在相位测量上没问题，但本项目已有明确结论：**被顶过阈值的过阈不是尖峰**（`PhaseResponseSpec` 的「a driven threshold crossing is not a spike」）。一枚强脉冲可以把 `v` 抬到 1.2 以上并停在那里，截面判据会把这种伪影当作真实传输转发出去，形成幽灵中继。

所以运行器提供两种判据：

| 判据 | 触发条件 | 用途 |
| :-- | :-- | :-- |
| `SectionCrossing` | 每次截面上穿 | 复刻原型数值指纹；纯相位传感 |
| `PeakConfirmed` | 上穿后峰值达到 `1.8` | 游戏层默认；伪过阈不转发 |

`PeakConfirmed` 的代价只是上冲段（1.2 → 1.8）的确认延迟，**不是**一整个周期：报给链路的时间仍是截面穿越时刻，因此不会改变「拍点」语义，只把幽灵传输挡在门外。`PulseCouplingSpec` 用两条手搭轨迹把这一点钉死：`1.25 → 1.4` 的停顿在 `SectionCrossing` 下被转发、在 `PeakConfirmed` 下不被转发；真正的尖峰（峰值 1.9）两种判据都恰好转发一次。

两条实现注记（2026-11-07）：

- **穿越时刻插值**：截面上穿时间在探针间做线性插值（与 `PhaseTracker` 同一纪律），粗步长下链路报告的相位不再被步长量化；指纹断言容差（±0.10–0.30）远大于插值修正量（< dt），原型数值不受影响。
- **确认窗焊死幽灵中继**：`PeakConfirmed` 增加 `SpikeConfirmWindow = 5.0`——实测真实上冲段 1.2 → 1.8 只需约 0.6（饱和）/ 1.2（近临界）个时间单位，越窗才爬到阈值的视为被驱动蠕变，候选**作废且永不补发**。此前「stall 缓慢爬过 1.8 仍被转发」的漏洞关闭。

## 3. 实验回执（与原型逐项对齐）

设置：`dt = 0.02`，饱和工作点 `a = -0.30`（`s = 1.0`），冻结慢变量，周期 `T ≈ 39.47`。下表「原型」列取自 Python 复现的实测输出，「本仓库」列由 `PulseCouplingSpec` 断言。

**游戏步长金样（2026-11-07 补）**：游戏实际积分步长是 `dt = 0.05`，同三台架实测——E1 锁定滞后 **−2.726**（std 远小于断言界 0.05）；E2 阈值锁定 **−10.329**（0.25 仍游走，std ≈ 0.70）；E4b 锁定 **−10.216** → 漂移后 **+5.960**。机制在粗步长下全部存活，数值漂移 < 0.1，已由 `PulseCouplingSpec` 的 game-dt 组钉死。

### 3.1 E1 双向耦合：锁相涌现，但不在零滞后

初始相位差 `0.33 T`（滞后 −13.03）。无耦合时滞后永远不动；耦合面积 1.0 时滞后收敛到约 −2.75 并稳定。

| 量 | 原型 | 本仓库 |
| :-- | :-- | :-- |
| 无耦合末段滞后均值 / 标准差 | −13.033 / 0.0058 | −13.033 / < 0.05 |
| 面积 1.0 末段滞后均值 / 标准差 | −2.748 / 0.0071 | −2.748 / < 0.05 |

这是真锁相（频率对齐 + 相位偏移有界），但平衡点**不在 0**：链路有延迟，且该工作点的 PRC 以推迟为主，双方互踢后停在小的非零偏移上。设计含义：**「山应合唱」的稳态是带固定偏移的合唱**，偏移量本身编码了 PRC 与链路延迟，是可被仪器测量的信息。

### 3.2 E2 耦合阈值：面积约 0.5

同周期单向耦合，观测窗 2500，末段 800 取统计：

| 耦合面积 | 原型末段滞后均值 / 标准差 | 判定 |
| :-- | :-- | :-- |
| 0.25 | −9.441 / 0.684 | 窗内仍在收敛，未锁 |
| 0.5 | −10.302 / 0.0064 | 锁定阈值 |
| 2.0 | −10.203 / 0.0064 | 强牵引，偏移略短 |

**锁定阈值约在面积 0.5（`tau = 2.0`，峰值约 0.09）**——这给「水晶品质」提供了机制刻度，而不是策划拍脑袋的数值：碎裂紫晶（< 0.25）只能传单次杂波，标准紫晶簇（0.5–1.0）可同温锁相，高纯共振晶棱（2.0）是强牵引。

### 3.3 E4b 漂移解体：已锁定的链路会被应力回落撕开

先让下游格与上游锁定（末段滞后 −10.198），`t = 1500` 起施加 `c = 0.10` 的安抚，下游应力从 1.0 匀速回落到 0。滞后随之单调滑过 0，最终停在 **+5.959**，总滑移约 **16.2** 个时间单位。下游仍在 `a = 0.70`（起振区）继续振荡，但**相位关系已被不可逆地改写**。

| 量 | 原型 | 本仓库 |
| :-- | :-- | :-- |
| 漂移前锁定滞后 | −10.198 | −10.198 ± 0.30 |
| 漂移后滞后 | +5.959 | +5.959 ± 0.30 |
| 滑移量 | 16.2 | > 10（断言） |
| 末态应力 | 0.0 | 0.0 |

另外一条定量结论：**灭火的代价约是放火的两倍**。自持振荡期 `q` 的反馈把应力钉在 1.0；要让 `c = 0.10` 拉得动 `u = 0.05` 的载荷，需要约 `c ≳ 2u`（原型试过 `c = 0.045`，完全压不动）。这条与「停手不能止灾」并列，是干预滞后的第二个身体证据。

## 4. 六条克制原则的回执

| 原则 | 回执 |
| :-- | :-- |
| 只加通道，不动四维方程 | ✅ 只经 `FirePulse`；契约指纹（`SliceContractSpec`）不受影响 |
| 链路不传应力 | ✅ 应力只由各格自身 `u/c/c0` 决定；`PulseLink` 无应力参数 |
| 黑箱配额 | — 叙事层决定（本札记不引入新叙事物件） |
| 用成本而非禁令 | ✅ 阈值面积 0.5 给出「水晶品质」刻度；没有「你不能连」的硬禁令 |
| 不给自动锁相 | ✅ **机制自带**：E4/E4b 证明固定延迟链路在漂移中必然失守，无需额外削弱 |
| 同步不写作文案 | ✅ 锁相 / 滑移是涌现现象，可直接目击 |

## 5. 设计含义（写给游戏层）

1. **水晶品质 = 耦合面积分档**。`< 0.25` 只能点亮、不能报讯；`0.5` 是「能锁」的门槛；`2.0` 是强牵引，但也会把伪影传得更远——判据选择因此重要。
2. **锁相稳态是非零偏移，偏移即信息**。跨区块通信不需要打破「只传脉冲不传应力」的克制：发送端微调耦合面积或相位偏置，接收端测稳态滞后，就是最物理的相移键控（Mandate-PSK）。
3. **固定延迟中继器必然滑移**（E4/E4b）。这是「玩家必须反复实测、必须能编程」的**机制依据**，不是策划禁令：想长期维持远端链路，就得用可编程电路周期性补偿相位（把 `lag` 测出来、在 `safe_tick` 窗口补一枚推迟脉冲）。
4. **灭火比放火贵**（`c ≳ 2u`）。安抚资源的投放要留滞后余量；「停手了就没事」在本机制里是不成立的。

## 6. 当前接线状态

- `MandateAgent.apply(..., links: Seq[PulseLink], spikeCriterion)`：链路投递在每步**之前**（`duePulses`），尖峰检测在每步**之后**（`observe`），与离线原型同序。运行器常驻；构造期 `links` 只是初始布线，运行期经拓扑事件 `AddLink` / `RemoveLink` 增删（2026-11-07，为晶盘/微网格与 worldgen 接线预留）。
- `PulseCoupling.runCoupled(...)`：离线复跑入口，格子无扩散边（链路是事件层），用于复刻实验。
- `MandateRuntime` 暂不注册链路：水晶元件与微网格尚未落地，等可编程晶盘（札记 09，待写）的方块交互定型后再经 `AddLink` 接入。链路已随 `MandateSnapshot` 持久化并在启动时恢复；目前只是还没有游戏侧发起 `AddLink` 的方块。
- **心跳簿记（2026-11-08，札记 08）**：链路投递的正脉冲与敲钟同等计入所在细胞的心跳抵消窗与耐受簿记（`MandateAgent.recordPulse`）。锁相链路周期 ≈ 39.5 s 远大于最小安全间隔（8 s），单条链路恰好能自动维持一个区块的沉滞庇护——「自动化心跳」由此涌现；多条链路汇聚同一细胞则有过密过载的风险，属保留观察的涌现特性。
- **突触解耦（既定方向，未实施）**：目前每格只有一个突触内核实例（`MandateState.synapseTau/Z/P`），`FirePulse` 到达时按发射器覆写 `synapseTau`——τ 不同的在途内核会互相改写衰减率（铃 5.0 与链路 2.0 叠加时），回放仍确定（发射器记录在事件里），但物理上不干净。方向是把内核状态移出 `MandateState`、挂到发射器/链路实体上（链路自有内核，铃击在 Agent 侧按 `PulseTransmitter` 分桶），格子只留一个 `synapseInput` 注入口，与 `stressFlux` 的接线模式一致；τ 随之彻底成为发射器/链路创建期配置。因必须改动契约哈希锚 `MandateState.scala`（金样需 `-Dvoy.contract.write=true` 重新生成并跨栈复核），原本与持久化搭车；持久化已于 2026-11-07 先行落地（未触契约锚），突触解耦仍待契约重生成窗口，不单独破契约。
