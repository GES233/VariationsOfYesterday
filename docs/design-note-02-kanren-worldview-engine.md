# 设计札记 02 — 动力学四相 × Kanren 关系引擎：多世界观透镜与「式盘」因果推导

> 状态：**概念发散与原型验证札记**（2026-10，配套沙盘脚本见 `scripts/kanren_sandbox.exs`）。
> 定位：在不触碰 `design-draft-01-living-world.md` §1 动力学冻结结构的前提下，探索如何以极简关系型编程（microKanren / cKanren）作为**符号桥接层**，将 `MandateReadout` 的离散相位枚举、地势有向拓扑、多套互异的世界观口径（老寨/官样文章/技术内参/退化新寨）以及玩法 Goals 统合进同一套不冲突的逻辑文法。

## 0. 核心痛点与破局思路

在《旧日变奏曲》的叙事与机制设计中，存在一个典型的工程与创作矛盾：
1. **多套世界观并行且容易写串戏**：原生老寨（民俗巫术口径）、总指挥部向上汇报（官僚掩饰口径）、基层技术员手簿（80 年代理工科半醒悟口径）、退化新寨（劳保服+拖拉机气缸的倒错工业祭祀）都在解释同一片山谷的灾变。如何保证多套世界观足够充实、互相印证形成「罗生门」，但又绝不在生成或组合时发生逻辑冲突？
2. **「科学复刻巫术」的同构判定**：设计草案提出「山地农业工程 = 仪式」、「被涂改的电路图还原后 = 装置合法构型」。如果靠硬编码 `if-else`，只能穷举死板的配方；如何让系统只认「动力学相位与拓扑约束」，从而涌现出「用工地废铁与交接班制度拼凑出合法镇山仪式」的诡异实感？
3. **不想背负重型知识库**：不同于需要百万级医疗三元组数据库的 `mediKanren`，本模组的底层物理现实（FHN 快慢方程 + 四相读数 + D8 汇流树）是**高度精简且 100% 确定性的**。

### 破局架构：连续动力学 + 关系型符号层的「神经符号系统」

- **底层（骨 / 连续数值）**：`MandateState` 与 `MandateGrid` 保持纯粹的四维 RK4 积分与算子分裂平流扩散，零逻辑规则侵入。
- **中间层（节 / 符号投影）**：`MandateReadout` 将连续状态 `(v, w, s, q)` 投影为离散的慢变量分级 `StressRegime`（`Calm` / `Strained` / `Oscillating` / `Burnout`）与快变量四相 `ExcitablePhase`（`Resting` / `Excitation` / `AbsoluteRefractory` / `RelativeRefractory`）。
- **上层（理 / Kanren 关系与 Goal 引擎）**：以 `MandateReadout` 枚举与 D8 地势有向边为唯一客观锚点（Ground Truth），通过 microKanren 的**双向求值（Relational Directionality）**、**开放特征匹配（Open Feature Unification）**与**不等约束（Disequality `=/=`）**驱动多世界观解释、仪式合成与溯因推理。

## 1. 藏骨于皮：「天地盘·四课·三传」的结构同构与去指涉转译

### 1.1 为什么底层结构酷似大六壬式盘？

本模组的动力学空间场与关系推理结合后，在结构上天然同构于中国传统式盘（大六壬「天地盘、四课、三传」）：
- **有静盘（地势）与动盘（相位）的加临**；
- **有主客器物与物候的并列待机（四课）**；
- **不作虚空占卜，唯因「所求之事（Goal / 触发事件）」而发用（三传）**：没有外部扰动或调制 Goal 时，天地盘只是当下切面的状态呈现；一旦发生点炮或敲钟（初传发用），气机便沿谷地平流移易（中传滞后 $\tau$），最终在下游坝子落定善恶之果（末传归宿）。

### 1.2 创作纪律：仅取结构，不取指涉

遵循 `design-draft-01-living-world.md` §0 的虚构原则，**游戏内文本、UI 与代码命名绝不直接出现「大六壬、天地盘、四课三传」等术数名词**，避免落入修仙/玄幻俗套；而是将这套严密的骨架彻底洗入 **1980 年代深山水文地质工程** 与 **虚构山地古谚** 的皮肉之中——让懂行者在看破机制时会心战栗，让普通玩家感受到纯粹的年代工业与民俗质感。

| 关系引擎结构（内部骨架） | 80s 工程队/水文站口径（理工行话） | 老寨残篇口径（虚构山民古谚） | 动力学与 Kanren 机制语义 |
| :--- | :--- | :--- | :--- |
| **静盘**（Static Plate） | **底图 / 汇流基底**<br>（等高线图、支沟断面号） | **山骨 / 落水架**<br>（哪条沟喝哪条涧的水） | `dipan_edgeo(up, mid, down)` + 聚落基线 $c_0$ 状态：决定因果单向顺沟下淌 |
| **动盘**（Dynamic Plate） | **相区 / 周期游标**<br>（对应 `MandateReadout` 四相） | **山息 / 潮候**<br>（起峰、退潮息、倒换气、平眠） | `tianpan_transitiono`：加临在底图各格上，决定此刻对脉冲是吸收、推迟还是引爆 |
| **四课**（Four Facets） | **工况切面 / 台账对照表**<br>（水文表 + 监听匣 + 作业单） | **四验 / 听山四对**<br>（看水纹、听虫鸣、验垂架、查香火） | `artifact_actiono` + `phase_phenomenono`：散落于山谷的主客器物与物候表征 |
| **三传**（Three Stages） | **起爆点 $\rightarrow$ 滞后传导 $\rightarrow$ 坝区响应** | **起手 $\rightarrow$ 过涧 $\rightarrow$ 落报** | `sanchuano(chu, zhong, mo)`：由具体 Goal 触发的「初传发端 $\rightarrow$ 中传平流 $\rightarrow$ 末传归宿」 |
| **式盘工具**（实物化） | **双层铝制水文计算转盘 / 穿孔排程卡** | **合木验山盘** | 下层刻本谷地高程节点，上层旋转透明盘刻四相窗口与滞后 $\tau$，玩家拨盘即在人脑中跑 Unification |

## 2. 多套世界观如何既充实又绝不冲突？

多套世界观打架的根源，往往是把「客观物理因果」与「主观阵营叙事」混在同一层谓词中。在 Kanren 中，只需引入 **1 个架构分层 + 2 个轻量语言机制**（在基础 microKanren 上仅需增加约 40 行代码），即可彻底解决：

### 2.1 唯一本体层 + 认知透镜（`Lens`）四元组

所有客观事件只在本体层（`sanchuano`）结算一次；所有叙事文本与归因逻辑必须通过 `lens_projectiono(Lens, Chuchuan, Zhongchuan, Mochuan, Record)` 投影生成：

```text
           [ 唯一本体三传 (Ground Truth Three Stages) ]
     初传: 野猪箐 + RelativeRefractory (易损窗) + 硝铵炸药点炮
     中传: 经断碑垭口平流 (τ=5) + 白水坝 c0_collapsed + Strained
     末传: 白水坝爆发 premature_excitation_spike (提前起峰)
                    ╱               │               ╲
      Lens: :OfficialHQ       Lens: :TechInner      Lens: :OldZhai
            ╱                       │                       ╲
           ▼                        ▼                        ▼
 《秋汛滑坡及自然损耗通报》  《水文手簿·夹页铅笔批注》   《白水老寨幸存者口述》
 「十月秋雨致常规岩移，      「当周滴雨未下！第4次点炮   「涧水起鱼鳞碎纹乃山脉
   已追加排险爆破根治」        正撞在簧片蜂鸣易损窗，      倒换气，四队拆铜钲断香火，
                               79年拆钟后c0归零致击穿」    又在换气口动火药致山神翻身」
```

### 2.2 两个关键的 Kanren 语言特性

1. **开放属性表匹配（`propso` / Open Feature Map）—— 像写词条卡片一样扩充设定**
   - 废除死板的多参数位置匹配（Positional Tuple），实体统一表示为键值属性表（Keyword List 或 Map）。
   - `propso(entity, required_kvs)` 只要求实体包含并合一指定的属性子集，其余风味字段自动保留。
   - **效果**：物理规则只约束 `[pulse: :alpha_metal_resonance, phase: :AbsoluteRefractory]`；至于这个脉冲是来自老寨的 `[name: "岁祭镇山铜钲"]` 还是退化新寨的 `[name: "红绸包裹的东方红-54气缸体", costume: "褪色劳保服"]`，物理方程一视同仁。

2. **不等约束（`neq` / `=/=`）—— 世界观防串戏防火墙**
   - 在 `State` 中维护一个轻量级不等式列表 `neq: [{u, v}, ...]`（每次 `unify` 成功后校验约 20 行代码）。
   - 用 `neq` 直接声明各世界观的**意识形态/认知禁忌（Taboo Rules）**：
     - 例如 `:OfficialHQ`（向上汇报材料）强制约束 `cause =/= :RelativeRefractory`、`cause =/= :c0_collapsed`、`cause =/= :mountain_god`，迫使求解器只能在合法替罪羊（如 `:autumn_rain_erosion` 秋汛滑坡）中合一；而数字（如失踪人数、日期代号）仍与本体层严格合一，自然生成「两套账本」的数字咬合与归因反差。

## 3. 六大可落地的玩法与设计期效果

### 3.1 退化新寨的「邪典工业仪式」自动合成（反向求解 Goal）
- **场景**：老寨改制为农场四队后，祖传铜钲被收缴（`c0_collapsed`）。工程队撤离后，留守职工在自持振荡期（`Oscillating`）面临生存 Goal：`outcome === :spike_delayed_by_8_6`（推迟灾变尖峰）。
- **涌现**：Kanren 在宿舍区残存的工业废料词条中反向搜索满足 `tianpan_transitiono` 的组合，自动将 **「林中虫鸣骤停/监听匣静默（20%–30% 绝对不应期）」+「按交接班条例列队唱名」+「大锤敲击红绸包裹的东方红拖拉机铸铁气缸」** 合一为合法的救命仪式。荒诞的形式与严肃的 FHN 方程在逻辑层严丝合缝。

### 3.2 「两套账本」与本地化 ARG 档案的约束编译
- **场景**：对抗 Wiki 剧透（设计草案 §4.1），每个世界种子的安全窗口、滞后常数 $\tau$、出事支沟代号不同。
- **效果**：在 Node 激活或世界生成时，以种子确定的本体参数运行 `lens_projectiono`，确保生成的表层公文、夹页批注、山民口述在拓扑与数字上 100% 互相咬合，且玩家从这组档案出发能够**唯一逆向合一（Unify 出唯一解）**出真正的调制参数。

### 3.3 设计期「设定集静态检查器（Lore Linter）」
- 在编写「文档圣经」与手写报告时，Kanren 可直接作为测试套件运行：
  - **漏判检测**：正如 `scripts/kanren_sandbox.exs` 初次运行所揭示的——当同一个叙事规则对 `regime: :Strained`（初犯击穿）和 `regime: :Oscillating`（持续振荡中二次点火）吐出完全相同的文本时，说明叙事颗粒度漏掉了关键的慢变量阶段区分。
  - **可解性验证**：验证给定的 $N$ 份档案碎片是否足以将未知逻辑变量 `?safe_phase` 收敛为唯一解（若解集长度 $>1$ 说明线索不足，若为 `[]` 说明线索自相矛盾）。

### 3.4 物候症候群与「老把式断山 / 勘测手簿」（双向因果网）
- **正向（呈现层）**：由上下游格子的 `(StressRegime, ExcitablePhase)` 组合推导跨格复合物候（如上游易损期 + 下游承压期 $\rightarrow$ 涧水鱼鳞驻波 + 沟口逆风）。
- **反向（玩家辅助推理）**：玩家在坝子观测到 `[水生鱼鳞波, 验山簧片蜂鸣]` 并填入勘测手簿（或询问寨老），Kanren 反向收敛出上游哪个支沟正处于 `RelativeRefractory` 以及是否存在常驻扰动源。

### 3.5 因地制宜的「土法调制工程」拓扑判定
- 玩家在垭口、汇流口搭建调制设施时，不检查死板的多方块结构模板，而是将设施连接关系提取为小型属性图，交由 Kanren 判定是否满足阻尼/脉冲调制关系——无论玩家用的是古寨石槽还是工地废旧导流管。

### 3.6 聚落群体 AI 的节律行为调度
- 寨民或留守职工的日常作息、恐慌聚集、守钟待机不再写死为复杂的状态机跳转，而是以当前区块的 `MandateReadout` 为输入，求解当前可行的群体生存 Goal；当关键器物（如钟）被破坏导致 Goal 返回空流 `mzero` 时，自动回退至次优/绝望替代分支（如盲目敲击铁器，甚至因相位不准而误触易损窗点火）。

## 4. 原型验证与后续 Scala 3 迁移路线

### 4.1 现有 Elixir 独立沙盘（无需 Java/Scala 环境即可迭代设定）
已在仓库 `scripts/kanren_sandbox.exs` 落地完整的单文件可执行原型：
- **内核（`Logic.Core`）**：包含带 `occurs?` 检查的 `unify`、交错搜索流（`mplus`/`bind` 公平搜索）、不等约束 `neq`（`=/=`）、多变量引入 `fresh/2` 以及开放属性表匹配 `propso/2`。
- **沙盘（`Voy.LiurenSandbox`）**：实现了「底图（地盘）— 相区（天盘）— 工况物候（四课）— 三阶传导（三传）— 多世界观透镜（Lenses）」完整闭环，并验证了三个核心推演：
  1. **推演一（溯因断案）**：由白水坝提前起峰（末传）反推 302 勘探队在野猪箐易损窗点炮（初传）及平流路径（中传），自动区分「从承压区 `Strained` 初犯击穿」与「在振荡期 `Oscillating` 二次点火」两种情形；
  2. **推演二（一案三表）**：对同一场事故自动衍生出 `:OfficialHQ`（秋汛通报）、`:TechInner`（手簿夹页铅笔批注一/二）、`:OldZhai`（山脉换气口述）四份视角各异且内部严丝合缝的档案记录；
  3. **推演三（邪典仪式合成）**：在铜钲遗失、陷入自持振荡的绝境下，为四队留守职工自动合成出「卡死死寂回吸期（`AbsoluteRefractory`）+ 监听匣静默 + 敲击红绸东方红-54气缸体」的替代司钟方案。

运行方式（在具备 Elixir 环境的终端下）：
```powershell
elixir scripts/kanren_sandbox.exs
```

### 4.2 后续向 Scala 3（`inner/`）迁移的工程要点
当切换至主开发环境并决定在具体分支施工时，将 `Logic.Core` 迁入 `src/main/scala/moe/chestnut/awa/voy/inner/` 极其轻量（预计约 150–200 行纯 Scala 3 代码，零外部依赖）：
1. **代数数据类型直接对接**：`Term` 可直接包裹现有的 `StressRegime` 与 `ExcitablePhase` 枚举（`MandateReadout.scala`），无需字符串转换；
2. **Stream 与 Goal 表达**：Elixir 的 `{:mature, h, t}` / `{:immature, f}` 直接映射为 Scala 3 的 `enum KStream[+A]`；`fresh` 配合 Scala 3 尾随闭包语法（`fresh: a => fresh: b => ...`），无需编写宏即可获得极佳的可读性；
3. **触发时机与性能隔离**：Kanren 求解器**绝不在每 tick 积分循环内调用**，仅在以下低频离散时刻触发：
   - 世界/Node 首次激活生成本地化档案与聚落初始历史时；
   - 区块 `MandateReadout` 发生跨相区/跨分级跃迁（Phase/Regime Transition）驱动聚落 AI 切换 Goal 时；
   - 玩家操作土法推演盘、勘测手簿或搭建调制工程触发拓扑验证时。
   全程纯内存不可变结构求值，单次查询耗时在微秒至亚毫秒级，完全符合 `design-draft-01-living-world.md` §1.4 的性能预算与加载不变性原则。
